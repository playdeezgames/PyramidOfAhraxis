# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## What this repo is

Pyramid of Ahraxis (itch.io: `thegrumpygamedev/pyramid-of-ahraxis`) is a small tile-map dungeon game written as a **TIC-80 Lua cartridge**. The goal of working here is to **reverse engineer it and port it to the Odin/WASM stack** (Odin compiled to `js_wasm32`), the same way `/home/yermom/git/wandermaze` was ported. That repo is the closest precedent: copy its layout (`tools/`, `src/game` + `src/web`, `web/index.html`) and its `CLAUDE.md` conventions rather than inventing new ones.

The game is the single cartridge `pyramid.tic` (68 KB, 240x136 map plus tiles, palette, sfx and music). There is no source tree. Treat these as non-source:

- `pub-*/` (git-ignored): platform exports of the cart with the TIC-80 runtime embedded.
- `.local/59ab359/`: TIC-80 IDE settings.
- `old/`: an **earlier, unrelated GNU COBOL text adventure** of the same name (room-based, N/S/E/W, character sheet; Jan 2023, IF Game Jam). The `README.md` log, TODOs, commands and inventory describe that COBOL game, not the cart. Do not port it unless asked.
- `help.md`: the TIC-80 1.1.2736 manual (API, RAM layout, key codes). Use it to look up `mget`, `fget`, `keyp`, `music`, `sfx`, `print` semantics.
- `cover.png`, `screen.png`, `mapimg.png`, `music.wav`, `map.map`: reference captures and exports (the cover is the pixel-parity target; `map.map` is a TIC-80 map export; `music.wav` is a recording of the music).

## Commands

Original cart (TIC-80 is not installed here; both scripts hardcode `/E/tic80-v1.1-win/tic80`, a Windows path from the author's machine):

- `launch.sh`: opens `pyramid.tic` in the TIC-80 IDE.
- `shippit.sh`: exports linux/win/mac/html, `butler push`es to itch, then `git add -A` and commits. **It publishes and commits; never run it unasked.** The Release standard replaces this with a `tools/ship.sh` plus a one-line wrapper that pushes only with `--push`; do that migration only as part of port work, never ship as part of it.

Extracting the cart without TIC-80: `.tic` is a sequence of chunks `[type(low 5 bits)|bank(high 3 bits)][size u16 LE][reserved byte][data]`. The Lua is the code chunk (type 5, ~4 KB, about 240 lines); the map chunk is 32640 bytes. Parse with a few lines of `python3 -I` (the Wandermaze `tools/extract_cart.py` is the model). `python3 -I tools/extract_cart.py [--dump DIR]` regenerates `src/game/assets.odin` (do not hand-edit; palette is Sweetie-16, tiles, flags and the post-BOOT map; all art is in the tiles chunk, the sprites chunk is absent). Sfx, music and waveform chunks (types 9, 10, 14, 15) are only dumped with `--dump`, not yet converted. `tools/test.sh`: native tests (51) plus `odin check` of both packages for `js_wasm32`. One test: `odin test src/game -define:ODIN_TEST_THREADS=1 -define:ODIN_TEST_NAMES=game.<test_name>`. `tools/ship.sh` (tests, size build, zip in `build/`; pushes to itch only with `--push`, which needs the user's say-so; `shippit.sh` is a wrapper) and `tools/make_assets.sh` (regenerates `assets/cover.png` and `assets/screenshots/`, needs Pillow) follow the bok Release standard; page copy is `ITCH_DESCRIPTION.md`. `tools/build.sh [--size]` builds `build/web` (git-ignored; serve with `python3 -m http.server -d build/web`). The restyle is merged into `main`, so the cover-parity check below no longer passes for the play/help screens (the old look is in git history, commit `987f5aa`; the `urizen-style` branch is redundant). The tooling remains: `odin test src/game -define:ODIN_TEST_THREADS=1 -define:DUMP_MENU=m.ppm` (also `DUMP_PLAY`, `DUMP_HELP`, `DUMP_SCORE`) then `python3 -I tools/compare_cover.py m.ppm cover.png`; at `987f5aa` the menu matched `cover.png` with 0 differing pixels. The current look is restyled: `python3 -I tools/extract_gfx.py` regenerates `src/game/gfx.odin` (14 Urizen 12x12 pictures from the vendored CC0 `tools/data/urizen_onebit_tileset__v2d0.png`, each painted in one Sweetie-16 colour; the cart's tile ids map to pictures in `tile_gfx`) and `src/game/font.odin` (DINOBYTE 6x8 from `tools/data/dbyte_1x.png`, CC BY 4.0, credit required). The play view is 15x11 cells of 12 px (HUD at x=184, 56 px wide), text is monospaced; there is no cover parity now. `tools/pages.sh` rebuilds `docs/` for GitHub Pages (https://playdeezgames.github.io/PyramidOfAhraxis/, live since October 29, 2026; commit `docs/` and `git push` to update; Pages serves `main` `/docs`). Levels: `tools/data/opd/*.json` are curated One Page Dungeon seeds (Watabou, https://watabou.itch.io/one-page-dungeon; the README there lists the order and why); `python3 -I tools/import_opd.py` regenerates `src/game/levels.odin` (do not hand-edit): one grid cell is one tile, everything outside the layout is wall, the entrance is the start, one door is a locked gate (the generator's type-5 door when every route passes it, else the door nearest the ending room that every route passes; tiles 3/4/5 = one/two/three locks, one key per lock), optional locked side rooms guard rewards, and keys, potions, jools, swords, shields, monsters and traps are placed by a seeded generator that checks solvability (monsters and traps never sit in a doorway, so nothing needs a fight). `LEVELS` is the play order and the last level is the cart's own map (`CART_LEVEL`); stepping on a level's exit loads the next, keeping health and items, and only the last goes to Score. F2 resets to level 1. Rules added to the cart's (all levels, the cart map too): a monster orthogonally beside you strikes when you step to a cell that is no longer beside it (shield blocks, else -1 heart; sliding along it or killing it first is free; a killing blow stops the step); a sword kill is clean (the cart's quirk, where the monster also hit back on the turn it died, was removed on October 29, 2026 at the user's say-so). Light and fog: you carry a light that burns 1 fuel per step (`g.fuel`, `Level.fuel` is granted on arrival, cap `FUEL_MAX`); radius 4 (torch), 6 once you pick up a lantern, 1 when the fuel is gone, and then the dark costs a heart every `DARK_BITE` steps, so the fuel is the clock; candle pickups (tile 133) add 60 and lanterns (134) 150; braziers (tile 6, solid) light radius 3 for good; walls, locked gates and braziers block light (Bresenham); lit cells are drawn in full, remembered cells (`g.seen`) dimmed without monsters, the rest black. Jools are money: bumping a merchant (tile 7, solid, one per level before the gate; not on the cart map) opens `Phase.Shop` (keys 1-6: potion 3, shield 2, sword 2, disarm kit 1, light +60 1, trap amulet 2; any other key leaves). Traps: hidden (tile 9) until sprung; the trap amulet (`g.sense`, radius `SENSE_RADIUS`) turns nearby ones into spotted traps (tile 10, drawn yellow), and walking onto a spotted trap uses a disarm kit (`g.ts`, tile 135 pickups or the shop) instead of springing it; some traps sit in corridors where they cannot be walked around. Wraiths (tile 67, solid): after every step each one beside you strikes, one that sees you within `CHASE_RANGE` steps closer (it rests every third step, so it can be outrun), the rest drift (seeded `g.rng`); a sword kills them like any monster. "+1 per level" counts of monsters, wraiths, traps and kits are in `tools/import_opd.py`. Each level has a `theme` (wall picture and colour, floor pattern; `THEMES` in render.odin; `tools/extract_gfx.py` supplies the pictures). Other door codes in the JSON are treated as plain openings. `src/game/game.odin` holds the rules (`command(&g, cmd)` is the single entry point; sounds are queued and drained with `take_sounds`).

TIC-80 `print` rules (verified against the cover): proportional glyphs are drawn starting at their leftmost lit column, advance = lit width + 1, a space advances 4; `shadow` draws the text at +1,+1 in the bg colour first. `spr`/`map` have no colour key by default (opaque, so the player and tile 0 cover what is below); `hline` and the jool icon use colour key 0. The page (`web/index.html`) owns key repeat (cart: `keyp(code, 10, 10)`) and plays Anvil-made WAVs from `assets/sfx/` (source world `assets/pyramid.world.json`; `SOUND_FILES` order must match `game.Sound`; `tools/build.sh` copies them to `build/web/sfx`), not the cart's sfx/music.

The Odin toolchain is `odin` on PATH (`~/.local/bin/odin`). Web builds: `odin build src/web -target:js_wasm32 -out:build/web/game.wasm -o:size`, copy `odin.js` from `$(odin root)/core/sys/wasm/js/`, and serve over http (not `file://`).

## Game design (recovered from the cart's Lua)

A top-down tile game on one 240x136 map; the original screen showed a 17x17 window of cells centred on the player (`map(x-8, y-8, 17, 17)`, player sprite drawn at 64,64) beside a HUD at x=136; the port shows 15x11 cells of 12 px with the HUD at x=184. State machine via the global `tf` (current screen function, `TIC()` just calls `tf()`): `Menu` -> `Help` or `Play` -> `Score` (reached by stepping on tile 8, the exit).

- **Tile index is behaviour.** Flags are read with `fget`: flag 7 = solid; solid + flag 6 = door (opens with a key, `mset` to 0). Special tile ids: 66 monster (solid; sword kills it, shield blocks a hit, else -1 health), 8 exit, 9 hidden trap (becomes tile 41 when sprung, -1 health), 128 key, 129 potion, 130 jool, 131 shield, 132 sword. Pickups are `mset(nx,ny,0)` on the live map, so the map is mutated in play and is restored only by `reset()` (F2).
- **BOOT** rewrites every map tile in 32..63 to `t-32` (a second, hidden layer of the map that is revealed as normal tiles at start). The port must apply the same transform to the extracted map.
- Player (`g.cs[1]`): start (21,11), health 3, keys, potions, jools, shields (`ds`), swords (`as`), kills (`ms`). Moves use `keyp(.., 10, 10)` (arrow codes 58 up, 59 down, 60 left, 61 right; hold 10, period 10 frames, so key repeat). P quaffs a potion (the cart used Q, code 17; the Urizen branch uses P): health back to 3. F2 (68) resets, F4 (70) exits. Menu: S starts, I opens help.
- Score = health*100 + kills*50 + jools*250 + keys*500 + potions*75. A dead player (health <= 0) sees sprite 65 and cannot move.
- Quirk, resolved: in the cart a sword kill also let the same bump resolve the shield/health branch (the monster hit back on the turn it died). Removed on October 29, 2026 at the user's say-so, once monsters began to strike when you step away; a sword kill is now clean (test `monster_sword_kills_cleanly`).
- Audio: `sfx` ids 0-3 for bumps/pickups/hits, `music` tracks 0-7 played as stingers (no loop) for death, shield, start, sword, jools, potion, quaff, exit. The cart's music and sfx data are in the cart; `music.wav` is a reference recording. Original sprites and map are 8x8 on the Sweetie-16 default or the cart's own palette: read the palette chunk, do not assume.

## Port architecture (follow Wandermaze)

`src/game` is pure Odin with no browser imports (rules, a 240x136 software framebuffer, TIC-80 `print` rules and font, generated asset data) and is imported via `-collection:tggd=src`; `src/web` (`#+build js`) only exports `proc "c"` functions; `web/index.html` owns `requestAnimationFrame`, input, `putImageData` and audio. Tests are `#+build !js` and run natively (`core:testing` breaks on wasm). Generated asset files are produced by a tool script and are not hand-edited. Seed the RNG yourself if any randomness is added (the original has none). `int` is 32 bits on `js_wasm32`. The built-in TIC-80 font is not in the cart; Wandermaze vendored MIT-licensed `font.inl` from the TIC-80 repo in `tools/data/`.

Verification: the menu was pixel-identical to `cover.png` before the deliberate Urizen restyle; now rely on the native tests and a browser check of `build/web` or `docs/`.
